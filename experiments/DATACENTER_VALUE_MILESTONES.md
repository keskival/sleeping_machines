## The first valuable demonstration

A customer-relevant AI workload reaches a stated quality level with lower
total cost, within its throughput, latency, memory and reliability requirements.
The model, compiler/runtime and eventual substrate form a combined product.
Software execution can establish capability and workload structure before
silicon. System energy needs a measured implementation and competent controls.

## Which costs a datacenter demonstration must include

- Training: data loading/preprocessing, all candidate discovery and losing-value
  credit, backward/replay, clipping/Adam, source-versioned checkpoint recovery,
  evaluation and separately reported search/tuning work.
- Inference: weight preparation, warmup/compilation, all key scores, selected
  proposals/writes, state/cache initialization and retention, request assembly,
  memory traffic and allocation, randomness/timing/communication and readout.
- Service: resident capacity per worker and per concurrent sequence, placement,
  admission/scheduling, batching, queue delay, failure recovery and update rollout.
- Hardware: measured compute/memory/control/clock/idle energy, latency and
  throughput at matched quality and precision. Logical tensor bytes are not
  measured DRAM bytes, and CPU FLOPs do not establish system joules.

Use per-completed scored target and whole-fit cost consistently; also show
evaluated positions when warm context/overlapping windows add work. Throughput
must count completed useful targets at the stated quality/latency, not just
internal events. Report construction once per weight version and amortize only
over requests actually served by that version. A new model version pays again.

## Priority and stop decisions

1. Preserve running fits; ingest completed outcomes automatically under their
   owner protocols. Pilot/online predictions stay separate from heldout quality.
2. Close backend correctness before associating its work counts with completed
   prediction scores. Prepare resource improvements that reuse the successful
   model rather than launch uncontracted credit variants.
3. Measure runtime gains before a system claim. Compare optimized ordinary
   execution and the prepared worker on the same physical reservation, model,
   inputs, precision, seeds and output mode. Include metadata guards and RNG.
4. Promote a model/core change on prespecified development evidence and retain
   independent confirmation. A narrow text8 result opens further evaluation;
   modern datacenter model quality still requires the frontier protocol.
5. Choose the first adoption route from measured capabilities: software/runtime,
   licensed accelerator IP, or systems. Do not assume a costly silicon program
   is necessary before obtaining a reproducible software/system proof point.

Fundraising material should link each technical claim to its immutable result,
producer hashes, protocol, controls, failure history and resource boundary.
The highest-value next evidence is a reproducible economically relevant
advantage, not a greater number of variants or an extrapolated valuation.
